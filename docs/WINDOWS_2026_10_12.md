# Physical Windows playback report review — 12 October 2026

The returned `evatex-results-new.zip` contains fresh real-game captures, rather than the previously duplicated headless report. The primary candidate jar SHA256 matches the immutable published 1.8.5-beta.1 Minecraft 1.21.11 artifact: `ab8062827809d66ce8ee6511b19704cfb54a477ab6d172888b165e6747a8f49b`.

The report covers 12 valid baseline/candidate runs plus six experimental patched runs, each 60 seconds, following warm-up. Frame timestamps are taken after the actual Minecraft OpenGL swap. The averaged FPS below was independently recalculated from each run's raw `frames.csv`; patch runs are kept separate from the published-candidate comparison.

Hardware: i5-3570, RX 580 2048SP, driver 31.0.12027.9001, Windows build 26200; Minecraft 1.21.11, Fabric 0.19.5, Java 21, 1280×720 framebuffer, VSync/60 FPS cap. The supplied Reze source is actually 1920×1080 at 60 FPS. Output is 30 FPS with the same video/config in both conditions. Audio remains muted at 10%. No 4K/8K playback was performed. The Windows machine has only one screen.

GPU Video Decode was active. GPU scaling fails on this driver with 80070057; the working fallback combines D3D11 decoding, CPU resizing/RGBA conversion, transport and OpenGL texture upload. Producing 1920×1080 RGBA for a 1280×720 window needlessly processes 2.25 times as many pixels. A separate 720p diagnostic and the patch repetitions support reducing that load. The original patch is `a2c32fa1f17da89ce04489d7cb72e995f88a3a53`, based on product source `93fd46439257cbd44c83454eb7f5c94bc78ba7d8`.

The framebuffer limit is incorporated into both shared source trees. The Linux integration additionally refreshes the Windows budget after a settled resize/fill-mode change; it separates publication locking from OpenGL upload and adds audio recovery and missing menu coverage. These additional changes were not present in the returned Windows patch measurements and require a new physical-Windows confirmation.

Long individual frames remained (up to 170.3 ms). Background CPU activity affected some repetitions, especially Atlas candidate r2; that run remains included and is not treated as a pure mod regression. The measurements support a substantial improvement on this configuration, not a universal smoothness guarantee or a claim that every remaining stall is caused by the user's PC.

World/options menu continuity, independent menu switches and actual loaded-world exclusion passed on both native and Atlas candidate runs. The Windows report did not enable audio, test looping sound, or test the final integration's live resizing and minimize/restore behavior. Small Atlas footer buttons had weak contrast on bright video frames; this remains a visual limitation of the returned capture.
